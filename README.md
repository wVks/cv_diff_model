# Разные методы генерации из диффузионных моделей

Этап 1: воспроизведение baseline на CIFAR-10 с замороженной моделью
`google/ddpm-cifar10-32` и готовым `DDIMScheduler` из Diffusers.
Обучение нейросети не выполняется.

В состав этапа входят подготовка данных, фиксированный набор начальных шумов,
проверка интерфейса модели и сэмплера, измерение FID/NFE/времени,
теоретический разбор DDIM, DPM-Solver++ второго порядка и Heun,
а также план экспериментов и подбора расписания.

Локальный прогон на Apple M4 Pro (MPS, float32): **FID 28.3151**, 50 NFE,
2048 generated / 10 000 test. Генерация заняла **433.97 с**, оценка FID —
63.76 с после подготовки данных. Обвязка совпала с `DDIMPipeline`
(максимальная абсолютная ошибка 0); пройдены 7 тестов.

## Окружение

Python 3.11–3.12. Проверенное локальное окружение: Python 3.12, PyTorch 2.9.1.
На macOS используется MPS, на NVIDIA — CUDA; доступен запуск на CPU.
Для macOS с новым загрузчиком требуется SciPy 1.17.1: старые сборки PROPACK
могут завершать импорт ошибкой `__thread_bss`.
Веса модели, CIFAR-10 и веса Inception загружаются автоматически.
Кэши и данные сохраняются внутри проекта, в `.cache/`.
Тестовая часть CIFAR-10 загружается из `uoft-cs/cifar10` организации University
of Toronto на Hugging Face, с зафиксированной ревизией и SHA256 файла.
Это позволяет загрузить только test (около 24 МБ), без полного архива train/test.

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

На GPU-платформах с установленным PyTorch применяется `requirements-gpu.txt`,
чтобы сохранить совместимую установленную сборку CUDA.

## Запуск

Все команды выполняются из корня репозитория.

```bash
# Короткий замер и оценка времени генерации полной выборки
python -u -m stage1 benchmark --device auto

# Генерация, расчёт FID и сохранение результатов
python -u -m stage1 run --device auto

# Независимая проверка численного расчёта FID по сохранённым признакам
python scripts/verify_fid.py

# Пересборка отчёта по фактическим результатам
python scripts/build_report.py --results artifacts/baseline/results.json
```

Генерация и оценка могут выполняться отдельно:

```bash
python -u -m stage1 generate --device mps
python -u -m stage1 evaluate --device mps
```

Повторный `generate` продолжает тот же прогон по сохранённым батчам.
Параметры и окружение проверяются по `manifest.json`; изменение конфигурации
требует нового каталога, например `--output artifacts/cuda_baseline`.
Для такого каталога путь также передаётся в `scripts/build_report.py --results`.

## Протокол baseline

- Готовая модель зафиксирована по commit SHA Hugging Face; все веса заморожены.
- DDIM: 50 шагов, `eta=0`, `epsilon`, `clip_sample=true`, `leading`, float32.
- Начальные шумы создаются на CPU одним генератором с seed `20261105`,
  сохраняются в `noise.pt` и сопровождаются SHA256.
- Основная выборка: 2048 сгенерированных изображений и 10 000 изображений
  `CIFAR-10 test`. Модель не дообучается; test используется только для оценки.
- FID: `torch-fidelity`, `inception-v3-compat`, 2048 признаков. На вход поступают
  RGB uint8 32×32; изменение размера выполняет сам экстрактор.
- NFE — число вызовов UNet на одно изображение. В JSON отдельно указаны
  реальные вызовы с батчами и суммарное число обработанных пар «изображение–шаг».
- Время генерации включает цикл денойзинга и перевод результата в float [0,1].
  Загрузка весов, прогрев, перенос начального шума, округление в uint8,
  запись файлов и расчёт FID измеряются отдельно либо исключаются.
- Короткий benchmark состоит из трёх повторов после прогрева. FID baseline
  рассчитывается один раз; оценка вариативности FID запланирована на этап 2.

FID на 2048 изображениях имеет заметное смещение и не сопоставляется напрямую
с опубликованными значениями на 50 000 изображениях. Сравнение будущих
конфигураций проводится при одинаковом числе изображений и одном протоколе.

## Сохраняемые артефакты

`results.json` содержит фактические метрики, параметры, версии библиотек,
контрольные суммы и время каждого батча. `real_indices.json` фиксирует
порядок реальных изображений. `generated_grid.png` и `real_grid.png`
показывают первые 64 изображения без ручного отбора.
В Git сохраняются компактные метрики и иллюстрации; веса, датасет,
полные тензоры шумов/генераций и признаки FID исключены через `.gitignore`.
Полный прогон восстанавливается командами выше.

## Границы этапа

В коде используется готовый DDIM из Diffusers, а собственная обвязка
проверяется по `DDIMPipeline` на одинаковых шумах. Собственные реализации
DDIM, DPM-Solver++ и Heun, поиск расписания и сравнение методов относятся
к этапу 2. Их устройство, план проверки и критерии успеха описаны в отчёте.
